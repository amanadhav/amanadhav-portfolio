Project 04 · 2026Distributed systems

ClassQ

Course registration built to prove it cannot oversell a section

Ten thousand students hitting one endpoint in the same second is the whole problem. Seat claims run as atomic Redis Lua scripts so two students can never take the same seat, full sections route to a sorted-set waitlist with a queue position, and prerequisite checks run as a BFS over the course DAG with a separate topological pass for cycle detection. A transactional outbox keeps event delivery off the registration hot path. A chaos button fires 500 concurrent registrations at a 30-seat section, then a correctness script asserts the invariant held. Provisioned end to end with Terraform.
